# 論文要約 HTML 生成: $ARGUMENTS

論文 (PDF / md など) を入力として、論文タイトル名のディレクトリを作成し、その配下に以下の2ファイルを生成する:

- `<論文タイトル>/summary.html` — 日本語要約 HTML
- `<論文タイトル>/<入力basename>.md` — markitdown 変換後の中間 Markdown

論文タイトルディレクトリは、ユーザーが後から手書きメモ (`notes.md` 等) を追加することを想定した置き場である。

## 1. 引数の解析

`$ARGUMENTS` から以下を抽出する:

- **入力ファイル** (必須): 第1引数。未指定ならエラーとして報告し終了
- **出力先親ディレクトリ** (任意): 第2引数。この直下に `<論文タイトル>/` を作成する
  - 未指定: 入力ファイルと同じディレクトリ
  - 指定された場合: 末尾の `/` 有無は問わずディレクトリとして扱う

`<入力basename>` は入力ファイルから拡張子を除いた部分。例: `/path/to/foo.pdf` → `foo`。
論文タイトルはステップ4で抽出する。

## 2. 入力ファイルの検証

- `test -f "<入力ファイル>"` で存在確認
- 存在しなければ「入力ファイルが見つかりません: <path>」と報告して終了

## 3. 論文タイトルの抽出と出力ディレクトリ確定

タイトル抽出のために、まず暫定で中間 md を準備する:

- 入力が `.md` の場合: そのファイルを直接 `Read`
- それ以外の場合: 一時的に冒頭部分を抽出する目的で、入力ファイルそのものを後段で変換する (ステップ5)。タイトル抽出のためだけに `markitdown` を先行実行する必要はない — 入力ファイル名や `Read` できる範囲から推定できない場合はステップ5で md 化してから戻ってきて再抽出する

タイトル抽出の手順:

- md の冒頭 (200 行程度) を `Read`
- Abstract 直前の論文タイトル (markitdown 出力では先頭付近に現れる) を Claude が判断して抽出
- ファイル名向けにサニタイズ:
  - 空白・カンマ等 → ハイフン
  - `/`, `:`, `*`, `?`, `"`, `<`, `>`, `|` などファイル名に使えない文字を除去
  - 長すぎる場合は 80 文字程度で切る

出力ディレクトリを以下に確定する:

```
<出力先親ディレクトリ>/<論文タイトル>/
```

## 4. 出力ディレクトリの準備と上書き確認

- `mkdir -p "<出力先親ディレクトリ>/<論文タイトル>"` で作成
- 同ディレクトリ配下に既存の `summary.html` がある場合は `AskUserQuestion` で「上書きする / キャンセル」を確認
  - キャンセルなら終了
- ディレクトリが既に存在しユーザーのメモ (`notes.md` 等) を含む場合でも、それらは絶対に削除・上書きしない

## 5. Markdown の準備

入力拡張子に応じて分岐し、出力先は `<出力先親ディレクトリ>/<論文タイトル>/<入力basename>.md` で固定:

- **`.md` の場合**: 入力をそのまま参照 (コピーはしない)。後段では入力 md パスを直接読む
- **それ以外 (PDF / DOCX / PPTX など)**: 以下で変換:

  ```bash
  uvx --from "markitdown[all]" markitdown "<入力ファイル>" -o "<出力先親ディレクトリ>/<論文タイトル>/<入力basename>.md"
  ```

  - 既に同名 md が存在する場合は再変換せず再利用する (上書き確認はしない)
  - 初回実行時は依存パッケージのダウンロードが走る (数十 MB)

中間 md は要約完了後も残置する。

## 6. 要約 HTML の生成

中間 md 全体を `Read` で読み込み (長い場合は分割 Read)、日本語で要約する。
HTML はテンプレート固定ではなく、論文の構成に合わせて内容を構築する。最低限以下を含める:

- **ヘッダー**: 論文タイトル (原題)、著者、会議/出版情報、外部リンク (あれば)
- **TL;DR ボックス**: 3〜5 行の要点
- **本文セクション**: 論文の構成に応じて「背景・動機」「手法」「実験・結果」「議論」「結論」など柔軟に
- **表**: 数値・比較は `<table>` で再構成する
- **個人的ポイント**: 末尾に印象に残った示唆・補足を入れる

スタイルは以下を満たす単一 HTML ファイル:

- 外部 CSS / JS 依存なし (`<style>` を `<head>` 内に内蔵)
- レスポンシブ (`max-width: 820px` 程度、`viewport` メタタグを含める)
- 日本語フォント優先 (`-apple-system, "Hiragino Sans", "Yu Gothic", sans-serif`)
- 見やすい配色 (淡い背景、十分なコントラスト、行間 1.7 以上)

`Write` で `<出力先親ディレクトリ>/<論文タイトル>/summary.html` に書き出す。

## 7. 完了報告

成功したら以下の形式で報告する:

```
要約完了: <入力> -> <論文タイトルディレクトリ>/
  - summary.html
  - <入力basename>.md  (PDF を変換した場合のみ)
```

失敗したら原因の要点を返す。

## 8. 制約

- 出力は必ず `<出力先親ディレクトリ>/<論文タイトル>/` 配下に限定する
- `summary.html` の上書きは必ず事前確認を取る
- 中間 md は再利用前提で残す (既に存在すれば再変換せず流用)
- 論文タイトルディレクトリに既存のユーザー作成ファイル (`notes.md` 等) があっても、絶対に削除・上書きしない
- 要約は日本語で書く。技術用語・固有名詞・モデル名は原表記を保つ
- 要約は元論文の主張を保ったまま構成する。事実の捏造・出典外の補足は行わない
