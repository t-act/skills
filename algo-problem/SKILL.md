# アルゴリズム問題ワークフロー

コーディングテストのアルゴリズム問題を解く際は、必ず以下の順序で進める。
いきなりコードを書き始めてはならない。評価対象は正解だけでなく、アプローチの明確さ・計算量の妥当性・コードの可読性である。

## Step 1: 問題の構造化

問題文から以下を抽出し、ユーザーに提示して認識を合わせる:

- **入力**: 形式、型、個数
- **出力**: 形式（改行、区切り文字、順序、丸め方まで正確に）
- **制約**: N の上限、値域、時間制限、メモリ制限
- **暗黙の条件**: ソート済みか、重複はあるか、負数・ゼロはあり得るか、空入力はあり得るか

引っ掛け要素がある前提で読む。「問題の意図を汲み取れているか」が評価される。
問題文に曖昧さがあれば、両解釈での挙動の違いを明示する。

## Step 2: 計算量の逆算

制約からアルゴリズムの許容計算量を決める。目安（1秒 ≒ 10^7〜10^8 演算、Pythonは低めに見積もる）:

| N の上限 | 許容計算量 | 典型手法 |
|---|---|---|
| N ≤ 10〜11 | O(N!) | 全順列 |
| N ≤ 20〜25 | O(2^N) | bit全探索、半分全列挙 |
| N ≤ 500 | O(N^3) | Floyd-Warshall、区間DP |
| N ≤ 5,000 | O(N^2) | 二重ループ、単純DP |
| N ≤ 2×10^5 | O(N log N) | ソート、二分探索、ヒープ、セグ木 |
| N ≤ 10^7 | O(N) | 累積和、しゃくとり法、篩 |
| N ≤ 10^18 | O(log N) / O(1) | 二分探索（答え）、行列累乗、数式 |

Pythonで時間制限が厳しい場合の対策は `references/python-perf.md` を参照。

## Step 3: 手法選定と方針の言語化

コードを書く前に、解法の方針を3〜5行で言語化する。この方針はそのままコード冒頭のコメント（docstring）として残す。アプローチの説明はテストで評価対象になる。

頻出パターンの選定ガイドは `references/patterns.md` を参照。

## Step 4: 実装

- python-code-quality スキルの規約に従う
- 入出力処理とロジックを関数分離する（`solve()` 関数パターン）
- 変数名は問題の意味を反映させる（`a, b, c` の濫用禁止。ただし添字 `i, j` や慣習的な `n, m` は可）
- 計算量をコメントで明記する

テンプレート:

```python
import sys

def solve(n: int, values: list[int]) -> int:
    """<解法の方針を記述>

    計算量: O(N log N)
    """
    ...

def main() -> None:
    input = sys.stdin.readline
    n = int(input())
    values = list(map(int, input().split()))
    print(solve(n, values))

if __name__ == "__main__":
    main()
```

## Step 5: 検証

edge-case-testing スキルを使い、以下を必ず実行する:

1. 問題文のサンプル入出力を全て検証
2. 境界値テスト（最小N、最大N、全て同値、等）
3. 最大制約でのローカル実行時間計測（`time` で計測し、制限の半分以内を目標）

## Step 6: 提出前チェック

- [ ] 出力形式が完全一致か（余計な空白・改行、大文字小文字）
- [ ] 全サンプルが通るか
- [ ] 最大ケースで TLE しないか
- [ ] オーバーフローの心配は不要（Python）だが、浮動小数点誤差はないか（可能なら整数演算で完結させる）
- [ ] 再帰を使う場合 `sys.setrecursionlimit` を設定したか
