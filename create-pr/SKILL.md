# PR 作成: $ARGUMENTS

以下の手順に従い、GitHub Pull Request を作成してください。

## 1. 事前チェック

- `git status` で未コミットの変更がないか確認する
- 未コミットの変更がある場合、ユーザーに確認してから続行する
- 現在のブランチ名を取得し、main / master でないことを確認する
- `gh auth status` で GitHub CLI のログイン状態を確認する

## 2. 差分解析

- `git log main...HEAD --oneline` でコミット一覧を取得する
- `git diff --stat main...HEAD` で変更統計を取得する
- 変更ファイルをカテゴリ別に分類する:
  - 機能追加 (新規ファイル)
  - 変更 (既存ファイルの修正)
  - 削除
  - テスト
  - 設定・CI/CD
  - ドキュメント

## 3. PR 説明文の生成

以下のテンプレートで説明文を生成する。コミットメッセージと差分の内容から適切に要約すること:

```markdown
## 概要
<!-- 変更の背景と目的を簡潔に記述 -->

## 変更内容
<!-- カテゴリ別に変更点をリスト化 -->

### 追加
-

### 変更
-

### 削除
-

## 関連 Issue
<!-- closes #xxx / refs #xxx -->

## テスト
- [ ] 既存テストが通ること
- [ ] 新規テストを追加した（該当する場合）
- [ ] 手動テストの内容:

## スクリーンショット
<!-- UI の変更がある場合に添付 -->

## チェックリスト
- [ ] コードが規約に従っている
- [ ] セルフレビュー済み
- [ ] 必要なドキュメントを更新した
- [ ] 破壊的変更がないか確認した
```

## 4. レビュアー提案

- `git log --format='%ae' -- <変更ファイル>` で過去のコミット者を取得する
- 自分自身を除外し、コミット数の多い順に最大 3 名を提案する
- `.github/CODEOWNERS` が存在すれば参照し、該当するオーナーも提案に含める
- レビュアー候補をユーザーに提示し、選択を求める

## 5. PR 作成

- 生成した説明文をユーザーに提示し、修正の有無を確認する
- ユーザーが承認したら以下を実行する:

```
gh pr create \
  --title "$ARGUMENTS" \
  --body "<生成した説明文>" \
  --assignee @me \
  --reviewer <選択されたレビュアー>
```

- PR が作成されたら URL を表示する

## 注意事項

- `$ARGUMENTS` が空の場合、コミットメッセージからタイトルを自動推定する
- base ブランチはデフォルトで `main` とするが、存在しなければ `master` を使う
- ラベルの自動付与は行わない（リポジトリ固有のため）
- draft PR にしたい場合はユーザーに確認する
